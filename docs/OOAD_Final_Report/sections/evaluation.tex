\section{Implementation and Evaluation}
\label{sec:evaluation}

\subsection{Implementation Environment}

This project implements the system in Java 21 and builds it with Maven.
The implementation uses Java Swing for the desktop interface, TeaVM 0.10.2 for the browser version, JUnit 5 for tests, and JaCoCo 0.8.14 for coverage.
The source code is publicly available \refRepository{}.
It contains about 8,300 lines of Java, of which about 3,150 belong to the desktop interface.

The analysis detected nine of the ten faults in this sample.

Figure~\ref{fig:wavetri} presents a tri-state buffer that drives a memory bus.
The bus starts as X and shows Z once the disabled buffer has passed its 5 ns delay.
It then follows the data line while the enable input is 1 and returns to Z when the enable input falls to 0.
The inverter reads the disconnected bus as X, which matches the rule that a gate cannot determine a value from a floating input.

Three further checks exercised the validation and comparison functions.
The checker reported the gate-level half adder sample and the library \texttt{HALF\_ADDER} macro as equivalent.
A second circuit used an OR gate in place of the sum logic.
The checker reported a counterexample at the input row where A and B are both 1.
The validator rejected a test netlist that connected an AND gate and a NOT gate in an unclocked loop.

\subsection{Test Coverage}
\label{sec:coverage}

All 122 JUnit test cases and all 22 self-checks pass on the final version of the code.
Table~\ref{tab:coverage} reports the JaCoCo results for each package.
The whole application reaches 55.8 percent line coverage, because the JUnit suite barely exercises the Swing interface in \texttt{simulator.gui}.
The code outside this package reaches 91.3 percent line coverage, or 2,436 of 2,668 lines.
This figure exceeds the 80 percent target for the domain logic and simulation engine.
Branch coverage falls below 80 percent in \texttt{simulator.core} and \texttt{simulator.application}, so the coverage claim applies to line coverage.

\subsection{Known Limitations}
\label{sec:limitations}

The present system has the following limitations.

\begin{itemize}
\item Each wire carries one bit, so the system has no multi-bit buses or integer truth tables.
\item The engine simulates expanded gates, so modules do not take part in event processing.
\item The FPGA placement, routing, and mapping of the reference paper fall outside the scope of this project.
\item Truth tables accept at most 16 inputs and flip-flops in total, because the table size doubles with each one.
\item The timing analysis omits flip-flop setup and hold times, and it does not identify paths that can never become active.
\item Stimuli scheduled for the same instant apply one after another. An intermediate combination can therefore produce a pulse of zero duration in the waveform, as the half adder sample shows at 110 ns.
\item The fault coverage analysis counts only differences between known values, so a fault that produces only X counts as undetected.
\item The scripted interface checks live outside the repository, so the JaCoCo figures do not include them.
\end{itemize}
